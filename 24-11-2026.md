# 1. Managing Users and Groups

Linux is a multi-user operating system. It allows multiple users to access the same system with different permissions and privileges.

Users and groups help administrators control access to system resources.

## 1.1 Understanding Linux User Accounts

Every Linux user account has:

- Username
- User ID (UID)
- Primary Group ID (GID)
- Home directory
- Default login shell

### Important Commands

```bash
# Display current username
whoami

# Display current user ID and group information
id

# Display all logged-in users
who

# Display currently logged-in username
users

# Display user account information
getent passwd

# Display a specific user
getent passwd username

# Display user account details
id username

# View user account database
cat /etc/passwd

# View password account information (requires root)
sudo cat /etc/shadow
```

### Understanding /etc/passwd

The `/etc/passwd` file contains basic user account information.

Example:

```text
kuladeep:x:1000:1000:Kuladeep:/home/kuladeep:/bin/bash
```

Fields:

| Field | Description |
|---|---|
| kuladeep | Username |
| x | Password placeholder |
| 1000 | User ID |
| 1000 | Primary Group ID |
| Kuladeep | User information |
| /home/kuladeep | Home directory |
| /bin/bash | Login shell |

### Creating Users

```bash
# Create a new user
sudo useradd username

# Create a user with a home directory
sudo useradd -m username

# Create a user with a specific shell
sudo useradd -m -s /bin/bash username

# Set user password
sudo passwd username

# Create a user interactively in Ubuntu
sudo adduser username
```

### Modifying Users

```bash
# Change username
sudo usermod -l newname oldname

# Change user's home directory
sudo usermod -d /home/newname -m newname

# Change user's login shell
sudo usermod -s /bin/bash username

# Lock a user account
sudo passwd -l username

# Unlock a user account
sudo passwd -u username

# Change user password
sudo passwd username
```

## 1.2 Working with Linux Groups

Groups allow administrators to manage permissions for multiple users.

Each group has a Group ID (GID).

### Important Commands

```bash
# Display current user's groups
groups

# Display groups of a specific user
groups username

# Display group information
getent group

# Display group database
cat /etc/group

# Display group ID information
id username
```

### Creating Groups

```bash
# Create a new group
sudo groupadd developers

# Create another group
sudo groupadd testers
```

### Adding Users to Groups

```bash
# Add user to a supplementary group
sudo usermod -aG developers username

# Add user to multiple supplementary groups
sudo usermod -aG developers,testers username

# Verify group membership
groups username
```

Important: The `-aG` options append supplementary group memberships. Avoid using `-G` without `-a` unless you intentionally want to replace existing supplementary group memberships.

### Removing Users from Groups

```bash
# Remove a user from a group
sudo gpasswd -d username developers
```

### Deleting Groups

```bash
# Delete a group
sudo groupdel developers
```

# 2. Working with Object Permissions

Linux permissions control who can read, write, or execute files and directories.

Every file and directory has three permission categories:

- Owner
- Group
- Others

## 2.1 Understanding Permission Notation Systems

Linux uses three main permissions.

| Permission | Symbol | Numeric Value | Meaning |
|---|---|---|---|
| Read | r | 4 | View file contents |
| Write | w | 2 | Modify file contents |
| Execute | x | 1 | Execute a file or access a directory |
| No Permission | - | 0 | No access |

### Understanding Permission Output

Run:

```bash
ls -l
```

Example:

```text
-rwxr-xr--
```

Explanation:

| Permission | Meaning |
|---|---|
| rwx | Owner can read, write, execute |
| r-x | Group can read and execute |
| r-- | Others can only read |

### Numeric Permission Notation

| Permission | Numeric Value |
|---|---|
| rwx | 7 |
| rw- | 6 |
| r-x | 5 |
| r-- | 4 |
| -wx | 3 |
| -w- | 2 |
| --x | 1 |
| --- | 0 |

Examples:

```bash
# Owner: full, Group: read/write, Others: read
chmod 764 file.txt

# Owner: full, Group: read, Others: read
chmod 744 file.txt

# Owner: full, Group: full, Others: no access
chmod 770 file.txt
```

---

## 2.2 Editing Object Permissions

The `chmod` command changes file and directory permissions.

### Numeric Method

```bash
# Give owner full permissions
chmod 700 file.txt

# Give everyone read permissions
chmod 444 file.txt

# Give owner full permissions and others read permissions
chmod 744 file.txt

# Give owner and group full permissions
chmod 770 file.txt
```

### Symbolic Method

```bash
# Add execute permission to owner
chmod u+x file.txt

# Remove write permission from group
chmod g-w file.txt

# Add read permission to others
chmod o+r file.txt

# Give everyone read permission
chmod a+r file.txt

# Remove all permissions from others
chmod o-rwx file.txt
```

### Recursive Permission Changes

```bash
# Change permissions recursively
chmod -R 755 mydirectory
```

Use recursive permission changes carefully because they affect all files and subdirectories.

---

## 2.3 Balancing Accessibility with Security

Linux permissions help protect sensitive information and prevent unauthorized modifications.

### Recommended Examples

```bash
# Private file
chmod 600 private.txt

# Publicly readable file
chmod 644 public.txt

# Private directory
chmod 700 private-directory

# Shared directory for owner and group
chmod 770 shared-directory
```

### Verify Permissions

```bash
ls -l file.txt

stat file.txt

stat -c "%A %a %n" file.txt
```

### Important Security Practices

- Give users only the permissions they require.
- Avoid unnecessary use of 777 permissions.
- Restrict access to confidential files.
- Use groups for shared resource access.
- Review permissions regularly.
- Avoid running applications as root unnecessarily.

# 3. Working with Object Ownership

Linux associates every file and directory with an owner and a group.

Ownership determines which user and group permissions apply.

## 3.1 Managing File and Directory Ownership

The `chown` command changes file or directory ownership.

### Check Current Ownership

```bash
ls -l file.txt

stat file.txt
```

### Change File Owner

```bash
sudo chown john file.txt
```

### Change Directory Owner

```bash
sudo chown john mydirectory
```

### Change Owner Recursively

```bash
sudo chown -R john mydirectory
```

### Change Both Owner and Group

```bash
sudo chown john:developers file.txt
```

---

## 3.2 Managing Group Ownership for Files and Directories

The `chgrp` command changes group ownership.

### Change Group Ownership

```bash
sudo chgrp developers file.txt
```

### Change Directory Group Ownership

```bash
sudo chgrp developers shared-directory
```

### Change Group Ownership Recursively

```bash
sudo chgrp -R developers shared-directory
```

### Verify Group Ownership

```bash
ls -l file.txt

stat file.txt
```

### Example: Shared Project Directory

```bash
# Create a shared directory
sudo mkdir /shared-project

# Create a development group
sudo groupadd developers

# Change group ownership
sudo chgrp developers /shared-project

# Allow owner and group full access
sudo chmod 770 /shared-project
```

---

## 3.3 Configuring Special Access

Linux provides special permission bits for additional access control.

The three important special permissions are:

1. SUID (Set User ID)
2. SGID (Set Group ID)
3. Sticky Bit

### SUID

SUID allows an executable program to run with the effective user ID of the file owner.

```bash
# Set SUID permission
sudo chmod u+s program

# Numeric method
sudo chmod 4755 program

# Verify permissions
ls -l program
```

The SUID permission is commonly visible as `s` in the owner's execute position.

### SGID

SGID allows an executable to run with the effective group ID of the file's group.

For directories, new files and subdirectories generally inherit the directory's group ownership.

```bash
# Set SGID
sudo chmod g+s shared-directory

# Numeric method
sudo chmod 2770 shared-directory

# Verify
ls -ld shared-directory
```

### Sticky Bit

The sticky bit on a shared directory restricts deletion of files inside it.

Users can generally delete or rename files in a sticky directory only if they own the file, own the directory, or have appropriate administrative privileges.

```bash
# Set sticky bit
sudo chmod +t shared-directory

# Numeric method
sudo chmod 1777 shared-directory

# Verify
ls -ld shared-directory
```

The `/tmp` directory is a common example of a directory with the sticky bit enabled.

### Verify Special Permissions

```bash
ls -ld /tmp

stat /tmp
```

# 4. Managing System Processes

A process is an executing instance of a program.

Linux provides several tools to monitor, control, and manage processes.

## 4.1 Monitoring Running Processes with ps

The `ps` command displays information about running processes.

### Basic Commands

```bash
# Display processes associated with the current terminal
ps

# Display all processes
ps -e

# Display detailed process information
ps aux

# Display processes in a tree structure
ps -ef --forest

# Search for a specific process
ps aux | grep python

# Display process IDs and command names
ps -eo pid,comm
```

### Understanding ps aux Output

| Column | Description |
|---|---|
| USER | Process owner |
| PID | Process ID |
| %CPU | CPU utilization |
| %MEM | Memory utilization |
| VSZ | Virtual memory size |
| RSS | Resident memory size |
| TTY | Associated terminal |
| STAT | Process state |
| START | Process start time |
| TIME | CPU time used |
| COMMAND | Command being executed |

---

## 4.2 Monitoring Running Processes with top

The `top` command displays real-time system and process information.

```bash
# Start process monitoring
top
```

Useful interactive keys inside top:

| Key | Function |
|---|---|
| q | Quit top |
| P | Sort by CPU usage |
| M | Sort by memory usage |
| k | Send a signal to a process |
| r | Change process priority |
| 1 | Toggle individual CPU information |

### Alternative Monitoring Command

```bash
# Display process information
top -b -n 1
```

This executes top in batch mode for one iteration.

---

## 4.3 Controlling Process Lifecycles

Linux provides commands to manage running processes.

### Find a Process

```bash
ps aux | grep python

pgrep python
```

### Terminate a Process

```bash
# Request graceful termination
kill PID

# Send SIGTERM explicitly
kill -15 PID

# Forcefully terminate a process
kill -9 PID
```

Replace `PID` with the actual process ID.

### Find Process by Name

```bash
pgrep nginx
```

### Terminate Processes by Name

```bash
# Request process termination
pkill nginx
```

Use `pkill` carefully because it may affect multiple matching processes.

### Display Available Signals

```bash
kill -l
```

---

## 4.4 Moving Processes to the Background

Linux allows processes to run in the foreground or background.

### Run a Command in the Background

```bash
sleep 100 &
```

The `&` symbol starts the process in the background.

### Display Background Jobs

```bash
jobs
```

### Suspend a Foreground Process

Press:

```text
Ctrl + Z
```

### Resume a Suspended Process in the Background

```bash
bg
```

### Resume a Background Process in the Foreground

```bash
fg
```

### Run a Command Without Blocking the Terminal

```bash
sleep 300 &
```

### Keep a Process Running After Logout

```bash
nohup sleep 300 > output.log 2>&1 &
```

The `nohup` command helps a process continue running after the terminal session ends, subject to system and session management behavior.

# 5. Managing System Log Operations

System logs help administrators monitor system activities, troubleshoot errors, and investigate system problems.

Linux commonly uses rsyslog and systemd-journald for logging.

## 5.1 Working with rsyslog Logging

`rsyslog` is a system logging service that collects, processes, and stores log messages.

### Check rsyslog Service Status

```bash
sudo systemctl status rsyslog
```

### Start rsyslog

```bash
sudo systemctl start rsyslog
```

### Stop rsyslog

```bash
sudo systemctl stop rsyslog
```

### Restart rsyslog

```bash
sudo systemctl restart rsyslog
```

### Enable rsyslog at Startup

```bash
sudo systemctl enable rsyslog
```

### View System Logs

```bash
# Display general system logs
sudo less /var/log/syslog

# Display authentication logs (Ubuntu)
sudo less /var/log/auth.log

# Display kernel messages
dmesg
```

Note: Some Ubuntu installations may not have rsyslog installed or enabled by default. Check its availability before using these commands.

---

## 5.2 Importing Remote Logs with rsyslog

rsyslog can collect log messages from remote systems.

It supports remote logging using protocols such as TCP and UDP.

### Check rsyslog Configuration

```bash
sudo nano /etc/rsyslog.conf
```

### Example: Enable UDP Remote Logging

Add or uncomment:

```text
module(load="imudp")
input(type="imudp" port="514")
```

### Example: Enable TCP Remote Logging

```text
module(load="imtcp")
input(type="imtcp" port="514")
```

### Restart rsyslog

```bash
sudo systemctl restart rsyslog
```

### Check Listening Ports

```bash
sudo ss -tulnp | grep 514
```

### Important Considerations

- Configure the receiving server to accept remote logs.
- Configure the sending server to forward logs.
- Configure firewall rules appropriately.
- Restrict access to trusted systems.
- Prefer secure transport and appropriate network protections for production environments.

The configuration above is an introductory example, not a complete secure remote logging deployment.

---

## 5.3 Understanding journald Logging

`systemd-journald` collects and manages system logs.

It stores structured log information in the system journal.

### Display Journal Logs

```bash
# Display all journal logs
journalctl

# Display logs from the current boot
journalctl -b

# Display the latest logs
journalctl -n 20

# Follow logs in real time
journalctl -f

# Display logs for a specific service
journalctl -u ssh

# Display logs from the current day
journalctl --since today
```

### Check journald Service

```bash
systemctl status systemd-journald
```

---

## 5.4 Filtering journald Logs

`journalctl` supports filtering logs based on service, priority, time, and other attributes.

### Filter by Service

```bash
journalctl -u nginx
```

### Filter by Priority

```bash
# Emergency messages
journalctl -p 0

# Critical messages
journalctl -p 2

# Error messages
journalctl -p err

# Warning messages
journalctl -p warning
```

### Filter by Time

```bash
# Logs since today
journalctl --since today

# Logs from the last hour
journalctl --since "1 hour ago"

# Logs within a specific time range
journalctl --since "2026-11-24 10:00:00" --until "2026-11-24 12:00:00"
```

### Filter by Boot

```bash
# Current boot logs
journalctl -b

# Previous boot logs
journalctl -b -1

# List available boots
journalctl --list-boots
```

### Follow Logs in Real Time

```bash
journalctl -f
```

## 6.4 Get Started with Linux Shell Scripting

### Objective

Understand the basics of shell scripting and learn how to automate Linux commands.

### Create a Shell Script

```bash
nano hello.sh
```

Add:

```bash
#!/bin/bash

echo "Welcome to Linux Shell Scripting"

echo "Current User: $USER"

echo "Current Directory: $PWD"

echo "Current Date: $(date)"
```

### Give Execute Permission

```bash
chmod +x hello.sh
```

### Execute the Script

```bash
./hello.sh
```

### Create Variables in a Script

```bash
#!/bin/bash

name="Kuladeep"
course="DevOps"

echo "Name: $name"
echo "Learning: $course"
```

### Conditional Statements

```bash
#!/bin/bash

read -p "Enter a number: " number

if [ "$number" -gt 10 ]; then
    echo "Number is greater than 10"
else
    echo "Number is 10 or less"
fi
```

### Loop Statements

```bash
#!/bin/bash

for i in 1 2 3 4 5
do
    echo "Number: $i"
done
```

### While Loop

```bash
#!/bin/bash

count=1

while [ "$count" -le 5 ]
do
    echo "Count: $count"
    count=$((count + 1))
done
```

- Understood shell script structure.
- Learned how to create and execute scripts.
- Practised variables and command substitution.
- Explored conditional statements.
