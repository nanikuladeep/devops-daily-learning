
# 🐧 Linux Networking, Packages, and Automation Basics

## 1. Managing Software on Debian/Ubuntu Systems

Ubuntu is based on Debian and uses the APT package management system to install, update, remove, and manage software packages.

### 1.1 Understanding the Debian Software Ecosystem

A software package contains application files, configuration files, dependencies, and installation instructions.

Important package management tools:

| Command | Purpose |
|---|---|
| `apt` | Manage software packages |
| `apt-get` | Perform package management operations |
| `dpkg` | Manage individual Debian packages |
| `apt-cache` | Search package information |
| `dpkg-query` | Query installed packages |

Check the Ubuntu version:

```bash
cat /etc/os-release
```

Check the APT version:

```bash
apt --version
```

View installed packages:

```bash
dpkg -l
```

Display information about a package:

```bash
apt show curl
```

### 1.2 Controlling Debian and Ubuntu Software Sources

Software sources are locations from which Ubuntu downloads software packages.

The main APT repository configuration is located in:

```bash
/etc/apt/sources.list
```

Additional repository configuration files may be stored in:

```bash
/etc/apt/sources.list.d/
```

View configured software sources:

```bash
cat /etc/apt/sources.list
```

List additional repository configuration files:

```bash
ls -l /etc/apt/sources.list.d/
```

Update the local package index:

```bash
sudo apt update
```

**Important:** `apt update` refreshes package information. It does not upgrade installed applications.

### 1.3 Working with Alternative Software Sources

Sometimes a required application is not available in the default Ubuntu repositories.

Alternative software sources can include:

- Personal Package Archives (PPAs).
- Official vendor repositories.
- Third-party repositories.
- Downloaded `.deb` packages.

Check whether the `add-apt-repository` command is available:

```bash
which add-apt-repository
```

Install the required supporting package if necessary:

```bash
sudo apt install software-properties-common
```

Example of adding a PPA:

```bash
sudo add-apt-repository ppa:example/ppa
```

The above PPA is an illustrative example, not a real repository to add.

Refresh package information:

```bash
sudo apt update
```

**Security note:** Only add repositories from trusted vendors. A third-party repository can introduce software and updates that affect your system's security.

### 1.4 Searching for Software Availability

Search for a package:

```bash
apt search nginx
```

Check package information:

```bash
apt show nginx
```

Check whether a package is installed:

```bash
dpkg -l nginx
```

Find the executable location:

```bash
which nginx
```

Search for installed package files:

```bash
dpkg -L nginx
```

### 1.5 Maintaining Your Software Packages

Update the package index:

```bash
sudo apt update
```

Upgrade installed packages:

```bash
sudo apt upgrade
```

Perform a full system package upgrade:

```bash
sudo apt full-upgrade
```

Install a package:

```bash
sudo apt install nginx
```

Remove a package:

```bash
sudo apt remove nginx
```

Remove a package and its system configuration files:

```bash
sudo apt purge nginx
```

Remove unnecessary dependencies:

```bash
sudo apt autoremove
```

Clear downloaded package files:

```bash
sudo apt clean
```

Check installed package information:

```bash
dpkg -l | grep nginx
```

**Difference between common APT commands:**

| Command | Explanation |
|---|---|
| `apt update` | Refreshes package information |
| `apt upgrade` | Upgrades installed packages |
| `apt install` | Installs a package |
| `apt remove` | Removes a package but generally retains configuration |
| `apt purge` | Removes a package and its system configuration |
| `apt autoremove` | Removes automatically installed dependencies that are no longer needed |

## 2. Managing Software on Red Hat Enterprise Linux Systems

Red Hat Enterprise Linux (RHEL), Rocky Linux, AlmaLinux, and Fedora use RPM-based package management.

Modern RHEL systems primarily use DNF (Dandified YUM) to install, update, query, and remove packages.

**Note:** These commands are for RHEL-based systems. Ubuntu uses APT by default, so DNF commands may not work in your current Ubuntu environment.

### 2.1 Installing Software Using DNF

Check the DNF version:

```bash
dnf --version
```

Install a package:

```bash
sudo dnf install nginx
```

Remove a package:

```bash
sudo dnf remove nginx
```

Update installed packages:

```bash
sudo dnf update
```

Upgrade the system:

```bash
sudo dnf upgrade
```

Search for a package:

```bash
dnf search nginx
```

Display package information:

```bash
dnf info nginx
```

### 2.2 Working with Repositories

Repositories are software storage locations that contain packages and package metadata.

List enabled repositories:

```bash
dnf repolist
```

List all repositories:

```bash
dnf repolist all
```

Display repository configuration:

```bash
ls /etc/yum.repos.d/
```

Refresh repository metadata:

```bash
sudo dnf makecache
```

### 2.3 Querying Packages and Repositories

Search for available packages:

```bash
dnf search python
```

Display package information:

```bash
dnf info python3
```

List available packages:

```bash
dnf list available
```

List installed packages:

```bash
dnf list installed
```

Find which package provides a particular command:

```bash
dnf provides /usr/bin/curl
```

### 2.4 Working with Installed Software Packages

List installed packages:

```bash
rpm -qa
```

Check whether a package is installed:

```bash
rpm -q nginx
```

Display package details:

```bash
rpm -qi nginx
```

List files installed by a package:

```bash
rpm -ql nginx
```

Find which package owns a particular file:

```bash
rpm -qf /usr/bin/bash
```

Remove a package:

```bash
sudo dnf remove nginx
```

### APT vs DNF

| Feature | Ubuntu/Debian | RHEL-based |
|---|---|---|
| Package manager | APT | DNF |
| Package format | `.deb` | `.rpm` |
| Package database tool | `dpkg` | `rpm` |
| Repository configuration | `/etc/apt/` | `/etc/yum.repos.d/` |
| Install package | `apt install` | `dnf install` |
| Update package index/metadata | `apt update` | `dnf makecache` |
| Upgrade packages | `apt upgrade` | `dnf upgrade` |

## 3. Working with Linux Networking Tools

Linux networking tools help administrators identify network interfaces, inspect IP addresses, check connectivity, understand network routes, and troubleshoot DNS issues.

### 3.1 Identifying Network Resources and Services

Display network interfaces and IP addresses:

```bash
ip addr
```

Short version:

```bash
ip a
```

Display network interfaces:

```bash
ip link
```

Display IP addresses only:

```bash
hostname -I
```

Display the system hostname:

```bash
hostname
```

Display detailed hostname information:

```bash
hostnamectl
```

Display listening network ports and services:

```bash
ss -tuln
```

Display listening ports with process information:

```bash
sudo ss -tulnp
```

Understand the options:

| Option | Meaning |
|---|---|
| `-t` | TCP connections |
| `-u` | UDP connections |
| `-l` | Listening sockets |
| `-n` | Numeric addresses and port numbers |
| `-p` | Display process information |

Check whether a service is running:

```bash
systemctl status ssh
```

Check network-related services:

```bash
systemctl --type=service --state=running
```

### 3.2 Assessing Network Connectivity and Status

Check connectivity to an IP address:

```bash
ping -c 4 8.8.8.8
```

Check connectivity to a domain:

```bash
ping -c 4 google.com
```

Display the routing table:

```bash
ip route
```

Check the default gateway:

```bash
ip route | grep default
```

Check whether a remote TCP port is reachable:

```bash
nc -zv google.com 443
```

Check HTTP response headers:

```bash
curl -I https://www.google.com
```

Check the route to a destination:

```bash
tracepath google.com
```

If `tracepath` is not installed:

```bash
sudo apt install iputils-tracepath
```

Alternatively, install traceroute:

```bash
sudo apt install traceroute
```

Run:

```bash
traceroute google.com
```

### 3.3 Understanding Your Network Environment

Display hostname:

```bash
hostname
```

Display IP configuration:

```bash
ip addr show
```

Display routing information:

```bash
ip route show
```

Display DNS resolver configuration:

```bash
cat /etc/resolv.conf
```

Display network interface details:

```bash
ip -s link
```

Display active network connections:

```bash
ss -tun
```

Display the default route:

```bash
ip route show default
```

Important networking concepts:

| Concept | Explanation |
|---|---|
| IP Address | Identifies a device on a network |
| Subnet Mask | Defines the network and host portions of an IP address |
| Gateway | Routes traffic to other networks |
| DNS | Converts domain names into IP addresses |
| DHCP | Automatically assigns network configuration |
| TCP | Connection-oriented communication protocol |
| UDP | Connectionless communication protocol |
| Port | Identifies a network service or application endpoint |

### 3.4 Troubleshooting DNS Issues

DNS (Domain Name System) translates domain names into IP addresses.

For example:

```text
google.com → IP address
```

Check DNS resolution:

```bash
getent hosts google.com
```

Use the `nslookup` command:

```bash
nslookup google.com
```

If it is unavailable:

```bash
sudo apt install dnsutils
```

Use `dig` to inspect DNS records:

```bash
dig google.com
```

Check DNS records for a specific record type:

```bash
dig google.com A
```

Display DNS resolver configuration:

```bash
cat /etc/resolv.conf
```

Check DNS resolution using curl:

```bash
curl -I https://google.com
```

#### Basic DNS Troubleshooting Process

1. Check whether the network interface is active.

```bash
ip link
```

2. Check whether the system has an IP address.

```bash
ip addr
```

3. Check whether the default gateway exists.

```bash
ip route
```

4. Test connectivity to an IP address.

```bash
ping -c 4 8.8.8.8
```

5. Test domain name resolution.

```bash
getent hosts google.com
```

6. Inspect DNS configuration.

```bash
cat /etc/resolv.conf
```

**Troubleshooting example:**

If this command works:

```bash
ping -c 4 8.8.8.8
```

But this command fails:

```bash
ping -c 4 google.com
```

The problem may be related to DNS resolution rather than general IP connectivity.

## 4. Automating Tasks Using Shell Scripts

Shell scripting allows administrators and developers to automate repetitive Linux operations.

Bash is a commonly used Linux shell.

### 4.1 Creating and Invoking Shell Variables

A variable stores information that can be reused in commands and scripts.

Create a variable:

```bash
name="Kuladeep"
```

Display its value:

```bash
echo $name
```

Create a variable for the operating system:

```bash
os="Ubuntu"
```

Display the variable:

```bash
echo "Operating System: $os"
```

Create multiple variables:

```bash
name="Kuladeep"
role="DevOps Learner"
os="Ubuntu"
```

Display all values:

```bash
echo "$name is a $role using $os"
```

**Important:** Do not add spaces around the `=` sign when assigning Bash variables.

Correct:

```bash
name="Linux"
```

Incorrect:

```bash
name = "Linux"
```

### 4.2 Exporting Shell Variables

An exported variable is available to child processes launched from the current shell.

Create and export a variable:

```bash
export PROJECT_NAME="DevOps Learning"
```

Display the variable:

```bash
echo $PROJECT_NAME
```

Check exported variables:

```bash
printenv PROJECT_NAME
```

List environment variables:

```bash
printenv
```

Another way to export a variable:

```bash
PROJECT_NAME="Linux Automation"
export PROJECT_NAME
```

Difference:

| Variable type | Explanation |
|---|---|
| Shell variable | Available in the current shell |
| Environment variable | Passed to child processes when exported |

### 4.3 Writing Simple Bash Scripts

A Bash script is a file containing Linux commands that can be executed together.

Create a script:

```bash
nano hello.sh
```

Add the following content:

```bash
#!/bin/bash

echo "Welcome to Linux Shell Scripting"
echo "Learning Linux Automation"
echo "Current User: $(whoami)"
echo "Current Date: $(date)"
```

Save the file.

Give execution permission:

```bash
chmod +x hello.sh
```

Execute the script:

```bash
./hello.sh
```

Alternatively:

```bash
bash hello.sh
```

#### Example: System Information Script

Create a file:

```bash
nano system_info.sh
```

Add:

```bash
#!/bin/bash

echo "===== Linux System Information ====="

echo "Username:"
whoami

echo "Hostname:"
hostname

echo "Operating System:"
cat /etc/os-release | grep PRETTY_NAME

echo "Current Date:"
date

echo "Current Directory:"
pwd

echo "Disk Usage:"
df -h

echo "Memory Usage:"
free -h

echo "===================================="
```

Execute:

```bash
chmod +x system_info.sh
./system_info.sh
```

### 4.4 Writing Interactive Bash Scripts

Interactive scripts accept information from users while executing.

Example:

```bash
nano user_input.sh
```

Add:

```bash
#!/bin/bash

echo "===== User Information ====="

read -p "Enter your name: " name
read -p "Enter your role: " role

echo "Hello, $name!"
echo "Your role is: $role"

echo "Welcome to Linux Automation!"
```

Execute:

```bash
chmod +x user_input.sh
./user_input.sh
```

#### Example: Interactive Calculator

```bash
#!/bin/bash

read -p "Enter first number: " num1
read -p "Enter second number: " num2

sum=$((num1 + num2))
difference=$((num1 - num2))
product=$((num1 * num2))

echo "Addition: $sum"
echo "Subtraction: $difference"
echo "Multiplication: $product"
```

#### Example: Check Whether a Number Is Positive or Negative

```bash
#!/bin/bash

read -p "Enter a number: " number

if [ "$number" -gt 0 ]; then
    echo "The number is positive"
elif [ "$number" -lt 0 ]; then
    echo "The number is negative"
else
    echo "The number is zero"
fi
```

## 5. Scheduling Automated Tasks

Task scheduling allows Linux administrators to execute commands or scripts automatically at specific times or intervals.

Linux provides multiple scheduling mechanisms:

1. Cron.
2. Systemd timers.
3. At.
4. Batch.

### 5.1 Automating Tasks Using the Cron System

Cron is a Linux scheduling service used to execute commands and scripts at predefined times.

Check the cron service:

```bash
systemctl status cron
```

Start the cron service:

```bash
sudo systemctl start cron
```

Enable cron at system startup:

```bash
sudo systemctl enable cron
```

Open the current user's crontab:

```bash
crontab -e
```

List scheduled cron jobs:

```bash
crontab -l
```

Remove the current user's cron jobs:

```bash
crontab -r
```

**Warning:** `crontab -r` removes all cron entries for the current user. Use it carefully.

#### Cron Syntax

Cron uses five time fields:

```text
* * * * * command
| | | | |
| | | | +---- Day of the week
| | | +------ Month
| | +-------- Day of the month
| +---------- Hour
+------------ Minute
```

Examples:

Run a script every minute:

```bash
* * * * * /home/user/script.sh
```

Run a script every day at 9:00 AM:

```bash
0 9 * * * /home/user/script.sh
```

Run a script every Sunday at 10:30 AM:

```bash
30 10 * * 0 /home/user/script.sh
```

Run a script every 5 minutes:

```bash
*/5 * * * * /home/user/script.sh
```

Run a script on the first day of every month:

```bash
0 0 1 * * /home/user/script.sh
```

#### Practical Cron Example

Create a script:

```bash
nano backup_time.sh
```

Add:

```bash
#!/bin/bash

echo "Backup job executed at $(date)" >> "$HOME/backup_log.txt"
```

Give execution permission:

```bash
chmod +x backup_time.sh
```

Open crontab:

```bash
crontab -e
```

Add this entry, replacing the path with the actual absolute path to your script:

```bash
*/5 * * * * /home/your_username/backup_time.sh
```

Check the output:

```bash
cat ~/backup_log.txt
```

This example writes a timestamp to a log file every five minutes.

### 5.2 Automating Tasks Using Systemd Timers

Systemd timers provide another method of scheduling automated tasks.

They work with systemd service units.

A timer unit determines when a service should execute.

Check systemd:

```bash
systemctl --version
```

List active timers:

```bash
systemctl list-timers
```

List all timers:

```bash
systemctl list-timers --all
```

Check a particular timer:

```bash
systemctl status example.timer
```

#### Example: Create a Systemd Timer

This is a system-level example and requires a working systemd environment.

Create a service file:

```bash
sudo nano /etc/systemd/system/backup-demo.service
```

Add:

```ini
[Unit]
Description=Demo Backup Logging Service

[Service]
Type=oneshot
ExecStart=/bin/bash -c 'echo "Backup executed at $(date)" >> /var/log/backup-demo.log'
```

Create a timer file:

```bash
sudo nano /etc/systemd/system/backup-demo.timer
```

Add:

```ini
[Unit]
Description=Run Demo Backup Every Five Minutes

[Timer]
OnBootSec=1min
OnUnitActiveSec=5min
Unit=backup-demo.service

[Install]
WantedBy=timers.target
```

Reload systemd configuration:

```bash
sudo systemctl daemon-reload
```

Enable and start the timer:

```bash
sudo systemctl enable --now backup-demo.timer
```

Check timer status:

```bash
systemctl status backup-demo.timer
```

List scheduled timers:

```bash
systemctl list-timers --all
```

View service logs:

```bash
journalctl -u backup-demo.service
```

Stop the timer:

```bash
sudo systemctl stop backup-demo.timer
```

Disable the timer:

```bash
sudo systemctl disable backup-demo.timer
```

### 5.3 Automating Tasks Using At and Batch

The `at` command schedules a command to run once at a specific future time.

The `batch` command schedules jobs to run when the system load permits.

Install the required package on Ubuntu:

```bash
sudo apt install at
```

Start and enable the scheduling service:

```bash
sudo systemctl enable --now atd
```

Check the service:

```bash
systemctl status atd
```

#### Using the At Command

Schedule a command for a specific time:

```bash
at 10:30
```

After entering the command, type:

```bash
echo "This task was scheduled using at" >> ~/at_log.txt
```

Press `Ctrl + D` to submit the job.

Schedule a task for tomorrow:

```bash
at tomorrow
```

Schedule a task after one hour:

```bash
at now + 1 hour
```

List pending jobs:

```bash
atq
```

Remove a scheduled job:

```bash
atrm JOB_ID
```

Replace `JOB_ID` with the actual job number shown by `atq`.

#### Using the Batch Command

Schedule a command using batch:

```bash
batch
```

Enter:

```bash
echo "Batch task executed at $(date)" >> ~/batch_log.txt
```

Press `Ctrl + D` to submit.

Batch jobs run when the system load permits, so they may not execute immediately.

### Cron vs Systemd Timers vs At vs Batch

| Tool | Purpose |
|---|---|
| Cron | Repeated scheduled tasks |
| Systemd timers | Scheduled systemd service execution |
| At | One-time scheduled tasks |
| Batch | Executes tasks when system load permits |

**Note for Ubuntu on WSL:** Some WSL installations do not run systemd or background services by default. Check whether systemd is active before attempting systemd timers, cron, or `at` service operations.

Check PID 1:

```bash
ps -p 1 -o comm=
```

If the output is `systemd`, systemd is running as the init system. If it is not, systemd-specific commands may not behave as expected.

# 6. Practical Linux Labs

The following labs are part of the hands-on learning activities.

## Lab 1: Monitor Linux System Processes

### Objective

Understand how to monitor running processes, identify resource usage, and manage process lifecycles.

### Step 1: Display running processes

```bash
ps
```

Display all processes:

```bash
ps aux
```

### Step 2: Monitor processes in real time

```bash
top
```

Press `q` to exit.

### Step 3: Identify a specific process

```bash
pgrep bash
```

Search for a process by name:

```bash
ps aux | grep bash
```

### Step 4: Display process details

```bash
ps -ef
```

Display processes in a tree format:

```bash
pstree
```

If unavailable:

```bash
sudo apt install psmisc
```

### Step 5: Terminate a process

Find a process ID:

```bash
pgrep sleep
```

Start a test process in the background:

```bash
sleep 300 &
```

Check the process:

```bash
pgrep sleep
```

Terminate it using its actual PID:

```bash
kill PID
```

Replace `PID` with the process ID returned by `pgrep`.

### Step 6: Check process status

```bash
ps aux | grep sleep
```

### Lab learning outcomes

- Understand Linux processes.
- Monitor running applications.
- Identify process IDs.
- Use `ps` and `top`.
- Start and terminate processes.

## Lab 4: Check and Apply Permissions to Files

### Objective

Understand Linux file permissions and practice changing permissions and ownership.

### Step 1: Create a test directory

```bash
mkdir permission_lab
```

Navigate into it:

```bash
cd permission_lab
```

### Step 2: Create a test file

```bash
touch sample.txt
```

Add content:

```bash
echo "Learning Linux File Permissions" > sample.txt
```

### Step 3: Check file permissions

```bash
ls -l sample.txt
```

Detailed information:

```bash
stat sample.txt
```

### Step 4: Apply numeric permissions

Give the owner read, write, and execute permissions, and give the group and others read permission:

```bash
chmod 744 sample.txt
```

Check the permissions:

```bash
ls -l sample.txt
```

### Step 5: Apply symbolic permissions

Remove write permission from others:

```bash
chmod o-w sample.txt
```

Give the group read and write permission:

```bash
chmod g+rw sample.txt
```

Remove execute permission from the owner:

```bash
chmod u-x sample.txt
```

### Step 6: Change file ownership

Check the current user:

```bash
whoami
```

Change ownership to a test user:

```bash
sudo chown testuser sample.txt
```

Change group ownership:

```bash
sudo chgrp devops sample.txt
```

Check the result:

```bash
ls -l sample.txt
```

These ownership commands assume that the `testuser` account and `devops` group have been created.

### Step 7: Apply directory permissions

Create a directory:

```bash
mkdir test_directory
```

Set permissions:

```bash
chmod 755 test_directory
```

Check permissions:

```bash
ls -ld test_directory
```

### Step 8: Understand numeric permissions

| Number | Permission | Meaning |
|---|---|---|
| 0 | `---` | No permissions |
| 1 | `--x` | Execute |
| 2 | `-w-` | Write |
| 3 | `-wx` | Write and execute |
| 4 | `r--` | Read |
| 5 | `r-x` | Read and execute |
| 6 | `rw-` | Read and write |
| 7 | `rwx` | Read, write, and execute |

For example:

```bash
chmod 755 script.sh
```

Means:

- Owner: Read, write, execute.
- Group: Read and execute.
- Others: Read and execute.

- Change file ownership using `chown`.
